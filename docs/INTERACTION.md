# RepoLens 交互规范

本文档是项目的交互契约。任何新增视图或控件，都必须能在这里找到对应的策略归属；
找不到归属的，说明它不该被加进来。

依据 Giles Colborne《简约至上：交互式设计四策略》——**删除、组织、隐藏、转移**。

代码仓库可视化的天敌是信息过载：1400 个文件、上万个符号，全画出来就是一团毛线球，
用户看到的第一眼就会放弃。四策略在这里不是装饰性的方法论，而是唯一能让这张图可读的手段。

---

## 策略一：删除（Remove）

> 去掉不必要的内容，直到剩下的每一个像素都在回答用户的问题。

### 默认只显示包级视图

打开浏览器的第一屏只有两样东西：

1. 顶部一句话的仓库简介（语言构成、包数量、总行数）
2. 一张 **10-30 个节点**的包 / 顶层目录架构图

文件不画，函数不画，第三方依赖不画。超过 30 个节点时，把最小的那些自动聚合成
一个「其他 N 项」节点，点击才展开。

### 节点上只显示一个主指标

节点内只有**名称**加**一个数字**（默认代码行数）。不显示文件数、复杂度、提交次数、
贡献者——这些全部移到 hover 卡片和详情面板。指标可在顶栏切换，但永远只显示一个。

节点大小编码该指标，边的粗细编码依赖强度。用视觉通道代替文字标签。

### 噪音默认不参与

以下文件默认从图和统计中排除，顶栏一个开关可全部放出来：

| 类别 | 判定 |
| --- | --- |
| 测试 | `*.test.*` `*.spec.*` `*.stories.*` `__tests__/` `__fixtures__/` `__snapshots__/` `*_test.go` `tests/` `testdata/` |
| 配置构建 | `*.json/jsonc/yaml/toml` `*.config.*` `Makefile` `Dockerfile` `*.lock` IDE/CI 配置目录 |
| 生成代码 | protobuf 常见后缀 `*.generated.*` `*.gen.*` `dist/` `generated/` 以及文件头的 `generated / do not edit` 标记 |
| 纯类型声明 | 只含类型/接口声明、无运行时导出的文件 |
| 第三方依赖 | `node_modules/` `vendor/` `third_party/` `.yarn/cache/` `Pods/` 等依赖目录 |

第三方依赖不是简单丢弃，而是**聚合成单个 `external` 节点**，保留「本仓库有多少边打向外部」
这个信息量，但不展开内部。

分类采用“项目显式规则优先、内置启发式兜底”：`.repolens.json` 的
`roleOverrides` 可以把任意 glob 强制指定为某个角色。无法确定时宁可保留为 `source`，
不因目录名包含 `scripts`、`tools`、`examples` 就武断隐藏真实逻辑。

### 不做的功能

明确拒绝进入 MVP：git 历史热力、贡献者统计、版本对比、导出图片、语义搜索。
它们都有价值，但都不是「看懂这个仓库」的必经之路，先做减法。

## 策略二：组织（Organize）

> 不减少内容，而是把内容组织成用户脑子里已有的结构。

### 三区布局，两侧默认收起

```
┌──────────────────────────────────────────────────────┐
│  顶栏：仓库名 · 体检 · 指标切换 · 噪音开关 · ⌘K       │
├────────┬────────────────────────────────┬────────────┤
│结构/体检│                                │  详情抽屉  │
│ (收起) │          图画布                 │  (收起)    │
│        │                                │            │
└────────┴────────────────────────────────┴────────────┘
```

中间画布是主角，占满宽度。左侧结构树和右侧详情抽屉都是**按需滑出**的覆盖层，
不挤压画布，关闭后画布尺寸不变——避免布局抖动导致用户丢失视觉焦点。
仓库下拉列表显示各仓库当前 Git 分支，并为已添加仓库提供“重新扫描”入口；
重扫沿用增量索引和现有进度条，重扫当前仓库完成后自动刷新画布。

### 按仓库自己的语言分组

分组依据不是算法聚类，而是仓库本身已有的边界，因为那才是用户脑子里的结构：

1. **monorepo 包**（`pnpm-workspace.yaml`、`go.mod`、Cargo workspace members、`pyproject.toml`）
2. 没有 workspace 时退化到**顶层目录**
3. 架构分层（M3 由 LLM 识别）作为**文字标签**叠加，而不是替代分组

目录树中的文件圆点、画布节点左侧色条、Hover 圆点和文件详情圆点都只编码**编程语言**；
目录使用中性的文件夹图标，不参与语言颜色编码，也不另设展开三角。目录和文件图标
从一级 13px 内边距开始，后续每层再增加 13px，
文件夹自身的开合形态表达展开状态。包、聚合节点没有明确语言时使用中性灰。AI 架构层只用文字标签表示，
不再占用颜色通道，避免同一种颜色在不同位置表达不同概念。

### 边的方向一致向下

ELK 分层布局，依赖方向统一自上而下。入口在顶部，基础设施在底部。
用户扫一眼纵向位置就知道谁依赖谁，不需要读箭头。

### 一个统一入口：⌘K

所有「我想去某个地方」的需求收进命令面板：跳转文件、跳转符号、切换视图、
执行操作。不在界面上散落十几个按钮。

### 体检结论挂在它涉及的节点上

架构体检不新开门面。结论按两种方式呈现，都落在用户已经在看的东西上：

- **节点角标**：问题数直接画在图节点右上角，且按路径前缀上卷——包级视图
  就能看出问题集中在哪个包，不必下钻到函数层才发现。角标只画一个点加一个
  数字，具体是什么问题去清单或详情里读；在节点上铺文字会把图变成报表。
- **左侧面板的第二个标签页**：体检清单和结构树是同一类「该去看哪里」的
  导航物件，所以共用槽位，不做弹窗或独立页面。

顶栏的体检入口**只在真有问题时出现**。没有问题时不该占位置，更不该显示
一个「0」让人反复确认——界面元素的存在本身就是一次对注意力的索取。

### 链路列表优先回答“哪些路径真的可追踪”

链路入口右侧数字表示从该入口到数据库、网络、文件系统等 I/O 边界的**静态路径数**，
不是运行次数。默认只展开显示路径数大于零的入口；暂时无法到达 I/O 的候选入口收进
“未形成链路的入口”，避免大量 `0` 淹没有效路径。测试入口跟随“显示杂项”开关，默认隐藏。

有效入口按 HTTP、CLI、main、公共 API、测试分组，同类中路径较多的排在前面；
未形成链路的候选沿用同一顺序。入口识别本身也保持克制：CLI 注册必须有明确的框架
接收者证据，模块导出只有位于包入口文件或由入口文件继续导出时才算公共 API。

链路详情把时间轴放在三条泳道左侧的独立窄列，圆点不压在卡片上；横向引线连接到
对应泳道卡片，卡片左边框继续用绿色实线/琥珀虚线区分确定步骤和静态推断。

### 跳转必须把图一起带过去

搜索结果和体检清单给出的都是深处的节点，而图只加载当前层。所以点击它们
走的是 `reveal`：向服务端问出从根到目标的展开链，逐层展开后选中目标。

只 `select` 不导航是个半成品——目标只出现在详情抽屉里，图停在原地，人还得
自己一层层下钻回去找它在结构里的位置。配套的两个约束：

- 请求每一层时都带上 `keep` 参数锁住目标所在的那一支，否则体量小的目标会
  被折进「其他 N 项」，画布上根本看不到它
- 视口优先整图适配；整图装不下时才跟着目标走，并夹在内容边界内，不让
  上方的兄弟节点被顶到可视区之外（它们藏在顶栏底下既看不见也点不到，
  而渐进下钻要求人随时能退回兄弟层）

## 策略三：隐藏（Hide）

> 把不常用但必要的功能藏起来，用渐进式披露在正确的时机呈现。

### 手势语义表

这是全局一致的约定，在任何视图、任何节点类型上含义都相同：

| 手势 | 行为 |
| --- | --- |
| **hover** | 浮出预览卡片（名称、类型、路径、一句话摘要、关键指标）；高亮直接相连的边与邻居，其余节点降到 32% 不透明度、边降到 20%（低细节缩放下不衰减） |
| **单击** | 选中，右侧详情抽屉滑出并填充；节点保持选中态高亮，抽屉不自动关闭 |
| **双击** | 下钻展开子节点（包→目录→文件→函数）；已展开则收起 |
| **⌥双击** | 以此节点为根重新布局，只看它的 N 层邻居（N 默认 1，可调） |
| **右键** | 上下文菜单：以此为根聚焦 / 隐藏此枝 / 只看入向边 / 只看出向边 / 在编辑器中打开 / 复制路径 |
| **拖拽** | 手动微调位置，位置记忆到 session |
| **滚轮** | 缩放；缩放到阈值以下自动切换为低细节渲染（只画色块不画文字） |
| **Esc** | 逐层退回：关抽屉 → 取消选中 → 退出聚焦 → 回到默认视图 |

设计取舍：**单击不下钻**。单击是最容易误触的手势，如果它触发图结构变化，
用户会在误触后丢失上下文。让它只做无损的「选中」，下钻交给双击这个明确的意图表达。

### 折叠与堆叠

折叠的节点组不是消失，而是渲染成**层叠卡片**——三张微微错位重叠的卡片，
右下角标注被折叠的数量。这个视觉隐喻同时传达了三件事：这里有东西、有多少、可以展开。

hover 层叠卡片时，整组卡片保持原尺寸和紧凑间距，仅通过阴影与连线高亮浮起；
不缩放节点，保证连接线端点不会偏离。完整名称和节点信息由 tooltip 承担。

### 逐级披露的详情

详情抽屉分标签页，默认只显示第一页：
左右侧边栏靠画布的一侧都可拖动调整宽度，宽度会保存在当前浏览器中；
聚焦分隔条后也可用左右方向键微调，双击恢复默认宽度。

| 标签 | 内容 | 何时加载 |
| --- | --- | --- |
| 概览 | 名称、签名、路径、指标、AI 摘要与伪代码 | 选中即加载，AI 内容生成后缓存 |
| 传参 | 参数表（名称、类型、默认值、是否可选）、返回类型 | 选中即加载 |
| 源码 | 语法高亮的原始代码片段 | 点开标签才加载 |
| 关系 | 调用方、被调用方、导入方，含置信度标注 | 点开标签才查询 |

### 高级控件藏进过滤抽屉

置信度过滤、深度上限、节点数上限、role 过滤、语言过滤全部收进一个过滤抽屉。
顶栏只留最高频的两个开关。

## 策略四：转移（Displace）

> 把复杂度转移到更适合承担它的地方。

### 重计算转移到扫描期

解析、解析导入、链接调用边、聚合汇总，全部在 CLI 扫描阶段一次性算完写进 SQLite。
浏览器里只做查询和渲染。用户等待的时间集中在一次显式的 `repolens scan`，
而不是分散成每次交互的卡顿。

### 布局计算转移到 Web Worker

ELK 布局是 CPU 密集的，放主线程会让拖拽和缩放掉帧。转移到 Worker，
主线程只负责渲染和手势响应。

### 全图遍历转移到 SQLite

「找两个节点之间的依赖路径」「找某节点 3 层邻居」这类图查询用 SQL 递归 CTE 在数据库里做，
不把全图搬到前端再用 JS 遍历。

### 语义理解转移给 LLM，结构判定不转移

这是最重要的一条分工：
- 「这个函数在做什么」「这个包属于哪一层」「这条链路的业务含义」→ LLM
- 「这个调用指向哪个文件的哪个函数」→ 确定性解析器，绝不交给 LLM

### 精确性取舍转移给用户

模块解析器解析不出来的 import（动态路径、复杂条件导入），不猜，
标记为 `unresolved` 并在 UI 上可查。用户看到「有 12 个 import 没解析出来」
比看到 12 条可能错的边要有用得多。

## 性能预算

交互设计的前提是不卡。目标规模（1400 文件 / 40 万行）下的硬指标：

| 操作 | 预算 |
| --- | --- |
| 首屏渲染 | < 500ms |
| hover 响应 | < 16ms（一帧） |
| 双击下钻（含 API + 布局） | < 300ms |
| 详情抽屉打开 | < 100ms |
| 全量扫描 | < 60s |
| 增量扫描（改 10 个文件） | < 3s |

任何交互超过 100ms 必须有即时的视觉反馈（骨架屏或进度指示），不能出现无响应的空白期。
