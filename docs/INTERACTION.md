# RepoLens 交互规范

本文档是项目的交互契约。任何新增视图或控件，都必须能在这里找到对应的策略归属；
找不到归属的，说明它不该被加进来。

依据 Giles Colborne《简约至上：交互式设计四策略》——**删除、组织、隐藏、转移**。

代码仓库可视化的天敌是信息过载：1400 个文件、上万个符号，全画出来就是一团毛线球，
用户看到的第一眼就会放弃。四策略在这里不是装饰性的方法论，而是唯一能让这张图可读的手段。

---

## 策略一：删除（Remove）

> 去掉不必要的内容，直到剩下的每一个像素都在回答用户的问题。

### 默认只显示包级视图

打开浏览器的第一屏只有两样东西：

1. 顶部一句话的仓库简介（语言构成、包数量、总行数）
2. 一张 **10-30 个节点**的包 / 顶层目录架构图

文件不画，函数不画，第三方依赖不画。超过 30 个节点时，把最小的那些自动聚合成
一个「其他 N 项」节点，点击才展开。

### 节点上只显示一个主指标

节点内只有**名称**加**一个数字**（默认代码行数）。不显示文件数、复杂度、提交次数、
贡献者——这些全部移到 hover 卡片和详情面板。指标可在顶栏切换，但永远只显示一个。

节点大小编码该指标，边的粗细编码依赖强度。用视觉通道代替文字标签。

### 噪音默认不参与

以下文件默认从图和统计中排除，顶栏一个开关可全部放出来：

| 类别 | 判定 |
| --- | --- |
| 测试 | `*.test.*` `*.spec.*` `*.stories.*` `__tests__/` `__fixtures__/` `__snapshots__/` `*_test.go` `tests/` `testdata/` |
| 配置构建 | `*.json/jsonc/yaml/toml` `*.config.*` `Makefile` `Dockerfile` `*.lock` IDE/CI 配置目录 |
| 生成代码 | protobuf 常见后缀 `*.generated.*` `*.gen.*` `dist/` `generated/` 以及文件头的 `generated / do not edit` 标记 |
| 纯类型声明 | 只含类型/接口声明、无运行时导出的文件 |
| 第三方依赖 | `node_modules/` `vendor/` `third_party/` `.yarn/cache/` `Pods/` 等依赖目录 |

第三方依赖不是简单丢弃，而是**聚合成单个 `external` 节点**，保留「本仓库有多少边打向外部」
这个信息量，但不展开内部。

分类采用“项目显式规则优先、内置启发式兜底”：`.repolens.json` 的
`roleOverrides` 可以把任意 glob 强制指定为某个角色。无法确定时宁可保留为 `source`，
不因目录名包含 `scripts`、`tools`、`examples` 就武断隐藏真实逻辑。

### 不做的功能

明确拒绝进入 MVP：git 历史热力、贡献者统计、导出图片、语义搜索。
它们都有价值，但都不是「看懂这个仓库」的必经之路，先做减法。

版本对比原本也在这张单子上，后来成了「变更」页签：读 AI 写的代码时，最常问的不是
「它现在长什么样」，而是「它这次改了什么、有没有越界」，这一条进了必经之路。

## 策略二：组织（Organize）

> 不减少内容，而是把内容组织成用户脑子里已有的结构。

### 三区布局，两侧默认收起

```
┌──────────────────────────────────────────────────────┐
│  顶栏：仓库名 · 体检 · 指标切换 · 噪音开关 · ⌘K       │
├────────┬────────────────────────────────┬────────────┤
│结构/体检│                                │  详情抽屉  │
│ (收起) │          图画布                 │  (收起)    │
│        │                                │            │
└────────┴────────────────────────────────┴────────────┘
```

中间画布是主角，占满宽度。左侧结构树和右侧详情抽屉都是**按需滑出**的覆盖层，
不挤压画布，关闭后画布尺寸不变——避免布局抖动导致用户丢失视觉焦点。
仓库下拉列表显示各仓库当前 Git 分支，并为已添加仓库提供“重新扫描”入口；
重扫沿用增量索引和现有进度条，重扫当前仓库完成后自动刷新画布。

结构树和画布分工不同：画布回答「主干是什么」，跟着噪音开关走；结构树回答「仓库里有什么」，
按磁盘逐层列出全部文件，不跟噪音开关走。参与分析的源码在前，按代码行排热度；
测试、配置、文档这类进了索引的噪音，以及没进索引的（`.gitignore` 排除、`node_modules`、
超大文件、第三方代码、扫描后新增）排在后面并置灰，没进索引的更淡一档，悬停说明原因。
灰色文件点开直接看源码：进了索引的照常有概览和关系，只是不自动生成 AI 摘要，要了再生成；
没进索引的只有原文。灰色目录单击即展开，因为它们不在画布上，没有概览可看。
`.git`、`.repolens` 这类版本库和索引元数据不列。

### 按仓库自己的语言分组

分组依据不是算法聚类，而是仓库本身已有的边界，因为那才是用户脑子里的结构：

1. **monorepo 包**（`pnpm-workspace.yaml`、`go.mod`、Cargo workspace members、`pyproject.toml`）
2. 没有 workspace 时退化到**顶层目录**
3. 架构分层（M3 由 LLM 识别）作为**文字标签**叠加，而不是替代分组

目录树中的文件圆点、画布节点左侧色条、Hover 圆点和文件详情圆点都只编码**编程语言**；
目录使用中性的文件夹图标，不参与语言颜色编码，也不另设展开三角。目录和文件图标
从一级 13px 内边距开始，后续每层再增加 13px，
文件夹自身的开合形态表达展开状态。包、聚合节点没有明确语言时使用中性灰。AI 架构层只用文字标签表示，
不再占用颜色通道，避免同一种颜色在不同位置表达不同概念。

### 边的方向一致向下

ELK 分层布局，依赖方向统一自上而下。入口在顶部，基础设施在底部。
用户扫一眼纵向位置就知道谁依赖谁，不需要读箭头。

边的样式只编码「这条依赖有多可信、是哪一类」，不编码别的：

| 样式 | 含义 |
| --- | --- |
| 实线，粗细随次数 | 运行时 import / 确定的调用 |
| 淡色细虚线 | 只有 `import type`：共享类型，不是运行时耦合 |
| 琥珀色虚线 + `HTTP` 标签 | 前端请求按 URL 对上后端路由，推断出来的 |
| 虚线 / 点线 | `likely` / `ambiguous` 调用 |

HTTP 边用标签而不只是颜色区分，因为它和 `likely` 调用同属推断，只靠虚线分不开；
详情抽屉的关系列表里同样带 `HTTP` 标记，悬停说明它没有 import 证据。

### 一个统一入口：⌘K

所有「我想去某个地方」的需求收进命令面板：跳转文件、跳转符号、切换视图、
执行操作。不在界面上散落十几个按钮。

### 体检结论挂在它涉及的节点上

架构体检不新开门面。结论按两种方式呈现，都落在用户已经在看的东西上：

- **节点角标**：问题数直接画在图节点右上角，且按路径前缀上卷——包级视图
  就能看出问题集中在哪个包，不必下钻到函数层才发现。角标只画一个点加一个
  数字，具体是什么问题去清单或详情里读；在节点上铺文字会把图变成报表。
- **左侧面板的第二个标签页**：体检清单和结构树是同一类「该去看哪里」的
  导航物件，所以共用槽位，不做弹窗或独立页面。

顶栏的体检入口**只在真有问题时出现**。没有问题时不该占位置，更不该显示
一个「0」让人反复确认——界面元素的存在本身就是一次对注意力的索取。

### 变更沿用同一套挂法

「变更」是左侧面板的又一个标签页，和结构树、体检、入口共用槽位，理由相同：它回答的也是
「该去看哪里」。打开时即对比，默认基线是 `HEAD`。换基线是从提交列表里点选，不是手敲提交号：
列表只收动过扫描根的提交（monorepo 里扫子目录时，没碰过它的提交快照都一样，列出来只是噪音），
每条带短号、标题、相对时间和分支 / tag。筛选框按标题、作者、分支、tag 和提交号前缀过滤，
列表里没有的（更早的提交、别的分支、`HEAD~n`）照样可以直接输入。点最新那条记成 `HEAD`，
之后再提交也跟着走；其他的按提交号记在当前浏览器里。

符号行不用原生 `title`：签名动辄上百字符，塞进系统提示框就是一坨不换行、没高亮的文字。悬停浮出
的卡片放在侧栏右边的画布上方，签名按语言高亮、在卡片宽度内折行。签名改了时新旧两版上下排，
按词比对后只给改动的几段加深底色——长类型里改了一个字段，一眼就能找到是哪个。

清单按审阅的先后排：先看新增了哪些模块依赖和外部库（架构有没有被悄悄改掉），再看哪些入口
会走到改过的代码（影响面），最后才是逐文件的符号清单。在当前图里还存在的条目都能点，走和
搜索一样的 `reveal` 导航；已删除的只列出来。

对比过一次之后，图节点上才出现变更角标：文件和符号标「新」/「改」，目录和包标 `Δn`
（下面有 n 个文件改过）——和体检角标一样按路径上卷，在包级视图就能看出改动落在哪几块。
没对比时不画，避免默认视图里多一层要解释的东西。

### 入口列表回答“从哪里开始读”

每个入口下面写着从它往下沿确定/可能的调用能走到多少个函数、跨几个别的文件，以及会碰到哪几类
I/O（数据库、网络、文件系统、消息队列、子进程）。按 HTTP、CLI、main、公共 API、测试分组，
同类里走得越远的排越前；处理函数没有独立符号、或者一个函数也走不到的入口收进
“走不到其他函数的入口”。测试入口跟随“显示杂项”开关，默认隐藏。入口识别保持克制：CLI 注册
必须有明确的框架接收者证据，模块导出只有位于包入口文件或由入口文件继续导出时才算公共 API。

I/O 只是标注，不是筛选条件。早先的「关键链路」只保留能走到 I/O 的最短路径，结果是大量真正
值得读的流程（纯计算、编排、渲染）不出现，出现的又是被截成一条线的片段。

### 单步走读模仿调试器，而不是画一张路径图

点入口（或详情抽屉里的「单步走读 →」、画布右键「从这里单步走读」）进入走读。界面借的是调试器
的心智模型，人不用重新学：

- **调用栈**在最上面，从入口到当前函数一格一格排开；和上一格不在同一个文件的，文件名用强调色，
  一眼看出这一步跨了文件。点任意一格回到那一层。
- **步骤列表**在左侧，是当前函数体内的调用，按静态求值顺序：实参里的调用先于外层调用，
  多行链式调用按每一段方法名所在的位置排。每一步写着它去哪个文件、往下会碰到哪类 I/O。
- **源码**在右侧，当前调用的方法名本身被高亮（不是整行），下面插一张卡片：解析档位、目标位置、
  实参、AI 一句话摘要（有缓存时）、目标函数里还有几处调用。多义调用在卡片上列出全部候选，
  由人选一个步入。
- **步入 / 跳过 / 步出**用方向键：↓ 下一步、↑ 上一步、→ 步入、← 步出，也认 `j/k/l/h` 和
  F10 / F11 / Shift+F11。走到函数末尾再按 ↓ 回到调用方的下一步，和调试器的 step over 一致。

默认只列能步入或带 I/O 的调用，内置函数和无法解析的调用藏起来，列表底部写着藏了几处；顶栏的
「全部调用」把它们一起列出（淡色、不可步入），偏好保存在当前浏览器。

落不到仓库里的调用要说清楚为什么，一律写「确定不了」等于什么都没说。外部调用分成「语言内置
`JSON`」和「外部库 `react`」；未解析的调用按原因给提示，例如「`setSummary` 是从 `useState()` 的
返回值里解构出来的函数，静态分析不追踪函数值」「`onClose` 是参数传进来的函数」「`store` 来自
`useAppStore()` 的返回值，推不出它的类型」。看提示就知道该去哪里找，或者知道这一步本来就不该
指望静态分析。

开始走读时，左侧面板和右侧详情抽屉原来开着就都留着：从入口面板连着点几个入口对比，或者从详情
抽屉的「单步走读 →」进来，都不用再把侧栏找回来。画布可以平移躲开浮在上面的面板，步骤列表和源码
不行，所以走读视图按两侧栏的宽度让出位置，拖动调整侧栏宽度也跟着变，调用栈、步骤列表和步进按钮
都不会被盖住。

### 跳转必须把图一起带过去

搜索结果和体检清单给出的都是深处的节点，而图只加载当前层。所以点击它们
走的是 `reveal`：向服务端问出从根到目标的展开链，逐层展开后选中目标。

只 `select` 不导航是个半成品——目标只出现在详情抽屉里，图停在原地，人还得
自己一层层下钻回去找它在结构里的位置。配套的两个约束：

- 请求每一层时都带上 `keep` 参数锁住目标所在的那一支，否则体量小的目标会
  被折进「其他 N 项」，画布上根本看不到它
- 视口优先整图适配；整图装不下时才跟着目标走，并夹在内容边界内，不让
  上方的兄弟节点被顶到可视区之外（它们藏在顶栏底下既看不见也点不到，
  而渐进下钻要求人随时能退回兄弟层）

### 结构树和画布双向联动

两边说的是同一个仓库，位置不该各管各的：

- **树 → 图**：在结构树里点一项，画布同样走 `reveal`，展开到它并居中。目录正好是某个包的根时，
  落到画布上的那个包节点。走读和调用图里只选中、不切走，人还在读的东西不该被一次点击打断。
- **图 → 树**：画布上选中什么（单击、搜索、体检清单、详情里的关系都算），结构树就一层层展开到
  它并滚过去高亮。选中的是函数时高亮它所在的文件，树只列到文件这一级。

### 聚焦时侧栏清单跟着收窄

图上聚焦到某个节点（⌥双击或右键「以此为中心聚焦」）之后，体检、入口、变更三个页签只列这个
节点里面的东西，顶部写着「只看聚焦的 X 里的」，点它就取消聚焦。收窄按包含关系算，不是图上的
N 层邻居：问的是「这块里有什么问题、有哪些入口、改了什么」，邻居的问题不归它管。

- 包和目录取路径下的全部，文件取它自己和里面的函数，函数只取它自己
- 变更里的入口除了自己在范围里的，走得到范围里改动的也留着，这正是「这块改了波及哪些入口」
- 模块依赖只在包和目录这两级有，聚焦到文件或函数时不列；外部库是整仓的，聚焦时也不列

结构树页签不收窄：它回答「仓库里有什么」，靠上面的联动定位就够了。

---

## 策略三：隐藏（Hide）

> 把不常用但必要的功能藏起来，用渐进式披露在正确的时机呈现。

### 手势语义表

这是全局一致的约定，在任何视图、任何节点类型上含义都相同：

| 手势 | 行为 |
| --- | --- |
| **hover** | 浮出预览卡片（名称、类型、路径、一句话摘要、关键指标）；高亮直接相连的边与邻居，其余节点降到 32% 不透明度、边降到 20%（低细节缩放下不衰减） |
| **单击** | 选中，右侧详情抽屉滑出并填充；节点保持选中态高亮，抽屉不自动关闭 |
| **双击** | 下钻展开子节点（包→目录→文件→函数）；已展开则收起 |
| **⌥双击** | 以此节点为根重新布局，只看它的 N 层邻居（N 默认 1，可调）；聚焦中照样双击展开，焦点和邻居展开出来的内容一起显示 |
| **右键** | 上下文菜单：以此为根聚焦 / 隐藏此枝 / 只看入向边 / 只看出向边 / 加入 AI 对话 / 在编辑器中打开 / 复制路径 |
| **拖拽** | 手动微调位置，位置记忆到 session |
| **滚轮** | 缩放；缩放到阈值以下自动切换为低细节渲染（只画色块不画文字） |
| **⌘I** | 展开追问 AI 并聚焦输入框；输入框已聚焦时收起 |
| **划选** | 在详情里选中一段源码或文字，旁边浮出「✦追问」，点击后作为引用加入对话 |
| **Esc** | 逐层退回：收起对话 → 关抽屉 → 退出走读 → 取消选中 → 退出聚焦 → 回到默认视图 |

设计取舍：**单击不下钻**。单击是最容易误触的手势，如果它触发图结构变化，
用户会在误触后丢失上下文。让它只做无损的「选中」，下钻交给双击这个明确的意图表达。

### 折叠与堆叠

折叠的节点组不是消失，而是渲染成**层叠卡片**——三张微微错位重叠的卡片，
右下角标注被折叠的数量。这个视觉隐喻同时传达了三件事：这里有东西、有多少、可以展开。

hover 层叠卡片时，整组卡片保持原尺寸和紧凑间距，仅通过阴影与连线高亮浮起；
不缩放节点，保证连接线端点不会偏离。完整名称和节点信息由 tooltip 承担。

### 逐级披露的详情

详情抽屉分标签页，默认只显示第一页：
左右侧边栏靠画布的一侧都可拖动调整宽度，宽度会保存在当前浏览器中；
聚焦分隔条后也可用左右方向键微调，双击恢复默认宽度。
左侧面板开没开、停在哪个页签，追问 AI 开没开，也一起记住，刷新或重开后还是上次的样子；
恢复出来的对话框不抢键盘焦点。详情抽屉跟着选中项走，选中项不记，所以它不恢复。

| 标签 | 内容 | 何时加载 |
| --- | --- | --- |
| 概览 | 名称、签名、路径、指标、AI 摘要，以及伪代码顶层步骤的提纲（每步一行，点击进入伪代码标签） | 选中即加载，AI 内容生成后缓存 |
| 传参 | 参数表（名称、类型、默认值、是否可选）、返回类型 | 选中即加载 |
| 伪代码 | AI 伪代码，每一步标注对应的源码行 | 与摘要同一次请求生成、同一份缓存 |
| 源码 | 语法高亮的源码，伪代码步骤作为注解插在对应行上方 | 点开标签才加载 |
| 关系 | 调用方、被调用方、导入方，含置信度和 `HTTP` 标注；调用方定位到调用发生的那一行，被调用方定位到它的定义 | 点开标签才查询 |

包和目录的概览在指标下面附上这一层自己的 README（只认直接放在这一层的，子目录里的归子目录）。
README 是作者写下的意图，AI 摘要是从代码反推的，两者并列才看得出「说的」和「做的」是否一致。

符号概览里的签名取源码原文的声明头，而不是索引里那份压成一行的签名：作者怎么换行、怎么缩进
就怎么显示，带高亮，到函数体之前截断，类里的方法去掉公共缩进。超过 12 行只露开头，点「还有 N 行」
展开。源码在扫描后改过、和索引对不上时，退回高亮并折行显示索引里的签名。
README 直接全文铺开，抽屉本身就能滚动，再折一层只是多点一下；点文件名进源码页。
渲染时链接只放行站外地址，图片不加载只留替代文字，内嵌 HTML 去掉标签留文字。

Markdown 文件的源码页右上角有「预览 / 源码」切换，预览与 README 用同一个渲染器、同样的安全限制。
默认显示预览，选择保存在当前浏览器；从笔记、伪代码等带行号的入口跳进来时临时切回源码，
否则没有行可定位，这次切换不改偏好。

仓库根在画布上没有节点，入口放在结构树顶部的仓库名上：点它打开仓库概览，即 AI 仓库概览、
仓库级指标和根目录 README。README 本身仍按文档归为噪音，默认不上画布。

伪代码和源码是同一份对应关系的两个阅读方向，而不是把两份内容并排塞进窄抽屉：

- **伪代码标签「先看提纲，按需下钻」**：悬停一步，对应源码浮在抽屉左侧的画布上方——看详情时
  画布恰好空闲，借这块空间比在抽屉里挤小窗好读；点击一步跳到源码标签并定位到那几行。不在伪代码
  里就地展开源码：悬停已经够看局部，要看上下文就该去源码标签，窄抽屉里再铺一份代码只会打断提纲。
  每步都能单独「追问」。
- **源码标签「读源码时手边有提纲」**：步骤注解插在它描述的代码上方，左侧色条标出每一步覆盖的
  范围；每一步都能折叠，全部折叠时退化成带行号的伪代码。注解可以整体关掉，偏好保存在当前浏览器。

步骤与行号的对应由模型在带绝对行号的源码上标注，入库前做确定性校验（颠倒的交换、越界的收进
范围、完全落在范围外的丢弃），界面上始终以 AI 强调色呈现并注明「可能有几行偏差」。旧缓存没有
行号时照常显示文字，提示重新生成后才能预览和定位源码。

语法高亮用 Shiki 在 Web Worker 里分词，语法按语言懒加载，颜色走 CSS 变量，随明暗主题切换。

### 追问 AI 停靠在详情抽屉底部

追问是「看到这里想问一句」，问题几乎总是关于正在看的东西，所以对话停靠在详情抽屉底部，
而不是另开一个面板或弹窗——问答时详情和画布都还在眼前。平时只占一行「追问 AI…」；展开后与
详情上下分栏，分隔条可拖动、双击复位；没有选中节点时对话占满侧栏。

上下文用输入框上方的 chip 表达，所见即所发：

- **自动附带**：当前选中的节点、当前视图（结构图展开到哪、调用图中心、走读的调用栈和停在哪一步），
  可以逐个移除；
- **手动加入**：划选源码或文字、伪代码某一步的「追问」、画布右键「加入 AI 对话」。

回答里提到的节点渲染成链接：悬停时画布高亮该节点并浮出预览卡，点击即沿展开链导航过去并打开
详情。每条回答可以展开「依据 N 项上下文」，查看服务端实际放进提示词的内容。浏览器只发送问题
文本和节点 id，源码、关系和已有 AI 解释由服务端按 id 现读，不接受任意路径。

这份上下文只是起点。不够时模型会自己去查：列目录、读文件（包括没进索引的配置、文档、脚本）、
全文搜索、按名字找符号、看调用关系、看 git 历史（log / show / blame / 未提交的改动），
允许时还会抓取公开网页（依赖库文档、issue）。查阅按需进行，问题答得出来就不调。
回答上方实时列出每一步「读取 xx L1–120」「搜索 yy」，答完收成一行「查阅 N 次」；
点文件那一步直接打开源码并定位到读过的行，点网页那一步在浏览器里打开。
模型或网关不支持函数调用时自动退回成只凭上下文回答。

### 高级控件藏进过滤抽屉

置信度过滤、深度上限、节点数上限、role 过滤、语言过滤全部收进一个过滤抽屉。
顶栏只留最高频的两个开关。

## 策略四：转移（Displace）

> 把复杂度转移到更适合承担它的地方。

### 重计算转移到扫描期

解析、解析导入、链接调用边、聚合汇总，全部在 CLI 扫描阶段一次性算完写进 SQLite。
浏览器里只做查询和渲染。用户等待的时间集中在一次显式的 `repolens scan`，
而不是分散成每次交互的卡顿。

### 布局计算转移到 Web Worker

ELK 布局是 CPU 密集的，放主线程会让拖拽和缩放掉帧。转移到 Worker，
主线程只负责渲染和手势响应。

### 全图遍历转移到 SQLite

「找两个节点之间的依赖路径」「找某节点 3 层邻居」这类图查询用 SQL 递归 CTE 在数据库里做，
不把全图搬到前端再用 JS 遍历。

### 语义理解转移给 LLM，结构判定不转移

这是最重要的一条分工：
- 「这个函数在做什么」「这个包属于哪一层」「走读到这一步在干什么」→ LLM
- 「这个调用指向哪个文件的哪个函数」→ 确定性解析器，绝不交给 LLM

### 精确性取舍转移给用户

模块解析器解析不出来的 import（动态路径、复杂条件导入），不猜，
标记为 `unresolved` 并在 UI 上可查。用户看到「有 12 个 import 没解析出来」
比看到 12 条可能错的边要有用得多。

## 性能预算

交互设计的前提是不卡。目标规模（1400 文件 / 40 万行）下的硬指标：

| 操作 | 预算 |
| --- | --- |
| 首屏渲染 | < 500ms |
| hover 响应 | < 16ms（一帧） |
| 双击下钻（含 API + 布局） | < 300ms |
| 详情抽屉打开 | < 100ms |
| 全量扫描 | < 60s |
| 增量扫描（改 10 个文件） | < 3s |

任何交互超过 100ms 必须有即时的视觉反馈（骨架屏或进度指示），不能出现无响应的空白期。
